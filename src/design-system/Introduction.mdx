# Energisa Design System

Bem-vindo ao Design System da Energisa. Esta é a documentação viva dos tokens,
componentes e padrões que formam a base visual de produtos digitais da empresa.

## Como este Storybook está organizado

A sidebar segue uma hierarquia em 2 camadas, do mais abstrato para o mais concreto:

### 1. Foundations
Os tokens crus do Design System — cores, tipografia, espaçamento, radius. Nada aqui
é um componente de UI; são os "ingredientes" que todo componente consome. Se você
precisa saber qual variável CSS usar para uma cor de marca ou um espaçamento, comece
aqui.

- **Colors** — primitives (valores crus) e semantic tokens (significado: `action-primary`,
  `surface-secondary`, etc.)
- **Typography** — escala de tamanhos, pesos e famílias de fonte
- **SpacingAndRadius** — escala de espaçamento e raios de borda
- **Grid** — sistema de colunas responsivo (tablet: 8 colunas / desktop: 12 colunas),
  extraído dos layout grids do Figma; disponível via classe utilitária `.ds-grid`
- **Icons** — biblioteca de ícones via Lucide React; galeria interativa com busca,
  controle de tamanho/espessura e exemplos de uso com tokens de cor

### 2. Components
Blocos de UI reutilizáveis, construídos exclusivamente a partir dos tokens de
Foundations. Nenhum componente define uma cor ou espaçamento próprio — tudo vem de
`var(--color-*)`, `var(--spacing-*)`, etc.

Cada componente expõe poucas stories na página "Docs" (referência rápida: variantes,
tamanhos, estados principais). Stories de cobertura exaustiva (testes de regressão,
combinações extras) existem no código mas ficam ocultas da view Docs — acesse pela
sidebar se precisar testar um caso específico.

## Regra de ouro

> Qualquer mudança visual começa no Figma. O código nunca define uma cor, espaçamento
> ou fonte "no olho" — sempre referencia um token. Se um valor não existe como token,
> a pergunta certa é "esse token deveria existir no Figma?", não "deixa eu colocar esse
> hex aqui mesmo".

## Convenção de nomenclatura

| Camada | Padrão | Exemplo |
|---|---|---|
| Figma (variável) | `categoria/conceito/escala` | `color/primitive/orange/500` |
| CSS (token) | `--categoria-conceito-escala` | `--color-primitive-orange-500` |
| Tailwind (uso) | `var(--token)` em classe arbitrária | `bg-[var(--color-action-primary)]` |

## Light & Dark mode

Todos os tokens semantic têm valores para os dois modos, definidos em
`src/styles/tokens.css` sob `[data-theme="dark"], .dark`. Componentes não precisam
de lógica condicional de tema — eles consomem o token semantic, e o valor certo é
resolvido automaticamente pelo CSS.

**Para avaliar qualquer componente no dark mode**: use o ícone de sol/lua na toolbar
do Storybook (topo da tela) e selecione **Dark**. Isso aplica `data-theme="dark"` no
`<html>` globalmente — todas as stories (inclusive a view "Docs") trocam de tema
instantaneamente, sem precisar de prop ou variante especial por componente.

## Storybook é a base da verdade do site

O site (`src/App.tsx` e futuras páginas) é construído em Tailwind v4 + padrões shadcn/ui e **nunca
consome um componente que não esteja documentado aqui primeiro**. Ao criar ou alterar um componente:

1. Implementar em `src/components/ui/`, só com tokens semantic.
2. Criar/atualizar a story correspondente em `src/design-system/`.
3. Atualizar o roadmap abaixo (e esta página, se for componente novo).
4. Só então usar no site.

**Patterns** (domínio "Reclamações/Tickets")
- [x] ComplaintCard — largura fixa 340px (conforme Figma, node 2505:1801);
  accent e badges variam por `level` (N1=info, N2=warning, N3=danger,
  External=purple) e por `status` (7 tons distintos); SLA fica no header ao
  lado do badge de prioridade (não no rodapé); badges na ordem Nível →
  Segmento → Status; rodapé tem avatar+responsável à esquerda e botão
  "Gerar" à direita (reaproveita `Button` ghost/md com ícone `FilePdf`,
  mesmo padrão do `ComplaintKanbanCard`)
- [x] ComplaintList — Header (11 colunas, coluna Tipologia flexível) + Row
  (accent 60% opacity), avatar+iniciais ao lado do responsável, coluna de
  **Ações** (botão de mais opções) e alerta de **dado inconsistente**
  (`inconsistent`) ao lado do número — ambos opcionais/ocultáveis. O ícone de
  inconsistência é o Phosphor `WarningOctagon` (ausente na lucide-react,
  incorporado em `src/components/ui/icons/`), cor `danger-default` conforme
  Figma, com tooltip ("Dado inconsistente") ao passar o mouse — ver regra de
  ícones no `CLAUDE.md`. O botão de Ações usa o Phosphor `DotsThreeOutlineVertical`
  (geometria diferente do `MoreVertical` da lucide-react), também incorporado
  em `src/components/ui/icons/`. As larguras das colunas são fixas e exatas
  do Figma (`clipsContent: true` em todas, confirmado via Plugin API no node
  2505:2156) — o texto de cada célula e o `Badge` truncam com reticências
  (`truncate`/`min-w-0`) em vez de recortar bruscamente quando o conteúdo é
  mais longo que a coluna (ex: status "Análise de Causa", nível
  "Consumidor.gov"). O hover do botão de Ações usa `hover-highlight` — o
  componente Figma por trás dele é o mesmo `Button / Icon` do IconButton/
  ThemeToggle/NavigationAvatar (fill real confirmado via Plugin API:
  `surface-tertiary`, branco no light), que só fica visível porque a linha já
  troca para `surface-secondary` (cinza) no hover antes do botão, dando o
  contraste necessário — diferente do `Button` ghost (que fica sobre fundo
  branco fixo, daí usar `surface-secondary` direto em vez de `hover-highlight`)
- [x] ComplaintKanban — Card (compacto, 3 states, com divisor antes do
  rodapé; SLA ao lado da prioridade no header; botão "Gerar" no rodapé,
  reaproveita o `Button` ghost/md, ícone Phosphor `FilePdf` exato do Figma) +
  Column (contador automático) + Board (7 colunas, scroll horizontal) —
  suporta **drag-and-drop nativo** entre colunas (`onCardMove`, coluna-alvo
  destaca com `isDragOver` enquanto o card está sobre ela). O hover/active do
  `Button` ghost usa `surface-secondary` (confirmado via Plugin API no fill
  do variant Ghost/Hover do Figma, node 2576:1691 — não `hover-highlight`,
  que é branco sólido e correto só em contextos de header sobre fundo
  colorido, nem `action-primary`/12%, que não corresponde ao fill real)
